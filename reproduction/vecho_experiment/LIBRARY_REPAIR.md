# 两条小项目试跑后的修复

修复版标记为 `library-v1`，在实验室独立目录部署，原始实验、首轮失败和恢复结果均保留。扫描与复核模型不变，不增加原有推理轮次。此次修复只做离线验证，没有新增付费实验。

## 具体改动

1. **库的调用边界**：扫描和复核均要求检查公共 API 的输入、返回值和安全契约。找不到仓库内生产调用方时，不能据此判断安全；引擎将识别到的这类排除理由保留为 `blocked`。模型必须说明外部使用上下文假设，不能编造调用链。
   有已读源码位置及文件哈希依据的 blocked 线索会以“待核实候选”交给 Judge，避免在阶段间再次丢弃；只有复核判真才进入最终告警，不附造漏洞路径。
2. **清洗阻断证据**：仅有 `s.sanitize()` 这样的调用行，不再足以关闭线索。声明阻断需要已读的实现分支或转换代码，以及具体约束、输出上下文、理由。模型自行填写的“已验证”标记会被覆盖。此检查验证证据结构，不是完整的语义证明。
3. **代码导航**：增加 `FindJavaSymbol`，过滤注释和字符串，按精确方法名定位候选声明，再用 `Read` 读取实现；重复检索及截断结果会提示换用精确定位或翻页，不增加推理轮次。工具是词法导航，不承担安全判定。
4. **结果表达**：正式增加 `location_match`，分别报告漏洞位置与标注方法是否重合、严格路径指标是否命中。不会为只有位置的 CodeQL 告警制造路径。
5. **实验隔离**：配置、编译运行时和阶段回执绑定分析策略。不能把旧扫描结果直接当成新策略的已完成扫描续用。
