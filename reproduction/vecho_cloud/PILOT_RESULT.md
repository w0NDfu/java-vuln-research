## 崩溃修复与结果保全

原进程在最终本地评测时发生 segmentation fault，留下 stale running 状态。
对同一份最终报告单独评测可重现崩溃。固定依赖为
`tree-sitter==0.25.2`、`tree-sitter-java==0.23.5` 后成功评分。
原版本为 tree-sitter 0.26.0。

恢复脚本验证了两个扫描 session 均 completed、两轮复核无失败，
最终报告完全等于复核通过记录去重后的集合；评分前后 SHA-256 保持一致。
恢复过程中没有重跑模型阶段。`recovery-audit.json` 保存了审计和依赖版本。
11 项离线测试在固定版本后全部通过。

后续评测在子进程内执行，使解析器崩溃能够被主进程记录为失败，
避免再次遗留无法区分的 running 状态。

## 复现边界及后续工作

当前扫描、复核与知识库问答使用 GPT-4.1 mini，Embedding 使用
text-embedding-3-small；并非论文的 GPT-4.1 主配置。
知识库初始为空，context 并发为 1，只进行一轮反馈重扫。
输入快照移除了 Git 历史、遮蔽 CVE 字符串，但保留项目与依赖名称，
因此只做了部分匿名化。历史 SAST 输入和作者知识库快照缺失。

120 个样本的源码已经准备好。本次仅证明低成本配置在一个样本上
走完扫描、复核、重扫及评分；不能据此推断全量检出率。
全量实验仍需运行剩余样本、保留失败与未解决记录，并对同一完成集合汇总。

关键文件：`run.json`、`final-report.json`、`evaluation.json`、
`recovery-audit.json`，以及两个阶段的 `usage.json` 和复核 `summary.json`。
